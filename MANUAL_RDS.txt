PASO 13: MODIFICAR REGLAS DE SEGURIDAD
---------------------------------------

IMPORTANTE: Por defecto, RDS no permite conexiones externas.
Debemos configurar el Security Group.

1. En la página de detalles de RDS, sección "Connectivity & security"

2. Encontrar "VPC security groups", click en el nombre: "rds-hackaton-sg"

3. En la pestaña "Inbound rules", click "Edit inbound rules"

4. CONFIGURAR REGLAS:

   Opción A - Para Desarrollo (acceso desde cualquier IP):
   ┌──────────────┬──────────┬───────────┬──────────────┐
   │ Type         │ Protocol │ Port Range│ Source       │
   ├──────────────┼──────────┼───────────┼──────────────┤
   │ MYSQL/Aurora │ TCP      │ 3306      │ 0.0.0.0/0    │
   └──────────────┴──────────┴───────────┴──────────────┘

   ⚠️ ADVERTENCIA: Esto permite acceso desde cualquier IP.
   Solo usar para desarrollo/pruebas.

   Opción B - Para Producción (acceso solo desde EC2):
   ┌──────────────┬──────────┬───────────┬──────────────┐
   │ Type         │ Protocol │ Port Range│ Source       │
   ├──────────────┼──────────┼───────────┼──────────────┤
   │ MYSQL/Aurora │ TCP      │ 3306      │ sg-xxxxx     │
   └──────────────┴──────────┴───────────┴──────────────┘

   Donde sg-xxxxx es el Security Group de tu instancia EC2

   Opción C - Para MySQL Workbench (acceso desde tu PC):
   ┌──────────────┬──────────┬───────────┬──────────────┐
   │ Type         │ Protocol │ Port Range│ Source       │
   ├──────────────┼──────────┼───────────┼──────────────┤
   │ MYSQL/Aurora │ TCP      │ 3306      │ Mi-IP/32     │
   └──────────────┴──────────┴───────────┴──────────────┘

   Click en "My IP" para usar automáticamente tu IP actual

5. Click "Save rules"


CONFIGURACIÓN RECOMENDADA POR CASO DE USO:

Caso 1 - Solo EC2 accede a RDS (MÁS SEGURO):
- Source: Security Group de EC2
- Ventaja: RDS no es accesible desde internet
- Desventaja: No puedes usar MySQL Workbench directamente

Caso 2 - EC2 + MySQL Workbench:
- Regla 1: Source = Security Group de EC2
- Regla 2: Source = Tu IP específica
- Ventaja: Seguro y puedes usar Workbench
- Desventaja: Si tu IP cambia, debes actualizarla

Caso 3 - Desarrollo rápido (MENOS SEGURO):
- Source: 0.0.0.0/0
- Ventaja: Funciona desde cualquier lugar
- Desventaja: Menos seguro, solo para desarrollo

PASO 15: CREAR TABLA DE EQUIPOS
--------------------------------

Una vez conectado en MySQL Workbench:

1. Verificar que estamos en la base de datos correcta:
   ```sql
   USE hackaton;
   ```

2. Crear tabla de equipos:

```sql
-- Eliminar tabla si existe (solo para desarrollo)
DROP TABLE IF EXISTS equipos;

-- Crear tabla equipos
CREATE TABLE equipos (
    id INT AUTO_INCREMENT PRIMARY KEY COMMENT 'ID único del equipo',
    codigo VARCHAR(50) NOT NULL UNIQUE COMMENT 'Código único del equipo (ej: LAB-001)',
    tipo VARCHAR(50) NOT NULL COMMENT 'Tipo de equipo (Laptop, Desktop, etc.)',
    marcas VARCHAR(50) NOT NULL COMMENT 'Marca del equipo (Dell, HP, Lenovo, etc.)',
    modelo VARCHAR(100) NOT NULL COMMENT 'Modelo específico del equipo',
    so VARCHAR(50) NOT NULL COMMENT 'Sistema operativo (Windows 11, Ubuntu, etc.)',
    almacenamiento INT NOT NULL COMMENT 'Capacidad de almacenamiento en GB',
    ram INT NOT NULL COMMENT 'Memoria RAM en GB',
    estado VARCHAR(50) NOT NULL COMMENT 'Estado actual (Disponible, En uso, Mantenimiento)',
    mantenimiento DATE NOT NULL COMMENT 'Fecha del último mantenimiento',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT 'Fecha de creación del registro',
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT 'Fecha de última actualización',
    
    -- Índices para mejorar rendimiento
    INDEX idx_codigo (codigo),
    INDEX idx_tipo (tipo),
    INDEX idx_estado (estado),
    INDEX idx_mantenimiento (mantenimiento)
    
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='Tabla de equipos informáticos';
```

3. Verificar que la tabla se creó correctamente:

```sql
-- Ver todas las tablas
SHOW TABLES;

-- Ver estructura de la tabla
DESCRIBE equipos;

-- Ver definición completa
SHOW CREATE TABLE equipos;
```

4. Insertar datos de prueba (opcional):

PASO 17: VERIFICAR CONEXIÓN DESDE PYTHON
-----------------------------------------

Crear script de prueba en tu PC o EC2:

```python
# test_rds_connection.py
import MySQLdb

# Configuración de conexión
config = {
    'host': 'hackaton-mysql-db.c9akciq32.us-east-1.rds.amazonaws.com',
    'user': 'admin',
    'password': 'TuPasswordSeguro123!',
    'database': 'hackaton',
    'port': 3306
}

try:
    # Intentar conectar
    print("🔄 Conectando a RDS...")
    connection = MySQLdb.connect(**config)
    
    # Crear cursor
    cursor = connection.cursor()
    
    # Ejecutar consulta de prueba
    cursor.execute("SELECT VERSION()")
    version = cursor.fetchone()
    print(f"✅ Conexión exitosa!")
    print(f"📊 MySQL version: {version[0]}")
    
    # Probar consulta a tabla
    cursor.execute("SELECT COUNT(*) FROM equipos")
    count = cursor.fetchone()
    print(f"📦 Total de equipos: {count[0]}")
    
    # Cerrar conexión
    cursor.close()
    connection.close()
    print("🔒 Conexión cerrada correctamente")
    
except MySQLdb.Error as e:
    print(f"❌ Error de conexión: {e}")
```

Ejecutar:

============================================
PARTE 10: TROUBLESHOOTING
============================================

PROBLEMAS COMUNES Y SOLUCIONES:

PROBLEMA 1: No puedo conectar desde MySQL Workbench
SOLUCIONES:
✓ Verificar Security Group permite tu IP (puerto 3306)
✓ Verificar Public accessibility = Yes
✓ Verificar endpoint correcto (copiado completo)
✓ Verificar credenciales (usuario: admin, no root)
✓ Verificar que RDS status = Available

PROBLEMA 2: Error "Access denied"
SOLUCIONES:
✓ Verificar contraseña correcta (mayúsculas/minúsculas)
✓ Verificar usuario existe: SHOW GRANTS FOR 'admin'@'%';
✓ Resetear contraseña: RDS > Modify > New master password

PROBLEMA 3: Error "Can't connect to MySQL server"
SOLUCIONES:
✓ Verificar endpoint completo (incluir región)
✓ Verificar puerto 3306
✓ Probar conexión: nc -zv endpoint 3306
✓ Verificar Security Group en VPC

PROBLEMA 4: Base de datos 'hackaton' no existe
SOLUCIONES:
✓ Verificar que pusiste "Initial database name" al crear RDS
✓ Crear manualmente: CREATE DATABASE hackaton;
✓ Verificar: SHOW DATABASES;

PROBLEMA 5: RDS muy lento
SOLUCIONES:
✓ Verificar CPU en Monitoring (CloudWatch)
✓ Ver conexiones activas: SHOW PROCESSLIST;
✓ Optimizar queries lentas: SHOW VARIABLES LIKE 'slow_query%';
✓ Agregar índices a tablas
✓ Aumentar instance class (db.t3.small, db.t3.medium)

PROBLEMA 6: Espacio en disco lleno
SOLUCIONES:
✓ Verificar Free Storage Space en Monitoring
✓ Habilitar Storage autoscaling
✓ Limpiar logs antiguos
✓ Eliminar datos no necesarios
✓ Aumentar allocated storage

PROBLEMA 7: Costos inesperados
SOLUCIONES:
✓ Verificar si estás fuera de free tier
✓ Revisar backups (costo después de 20 GB)
✓ Revisar snapshots antiguos (eliminar los no necesarios)
✓ Revisar transferencia de datos OUT
✓ Considerar Reserved Instances
