============================================
GUÍA DE DESPLIEGUE EN AWS EC2 CON MYSQL LOCAL
VERSIÓN DEBIAN
============================================

REQUISITOS PREVIOS:
- Instancia EC2 Debian 11 o 12 en AWS
- Clave SSH (.pem) para acceso
- IP Elástica asignada a la instancia

NOTA: Los comandos son casi idénticos a Ubuntu, con pequeñas diferencias
en el usuario por defecto y algunas configuraciones.


============================================
PASO 1: CONECTAR A LA INSTANCIA EC2
============================================

# Debian usa diferentes usuarios según la AMI:
# - admin (más común en AWS Debian)
# - debian (algunas AMIs)
# - root (no recomendado)

# Probar primero con 'admin':
ssh -i "ruta/a/tu/clave.pem" admin@tu-ip-elastica

# Si no funciona, probar con 'debian':
ssh -i "ruta/a/tu/clave.pem" debian@tu-ip-elastica

Ejemplo:
ssh -i "C:\Users\anacr\Downloads\ani.pem" admin@98.87.67.95

# Para identificar el usuario correcto:
# En AWS Console > EC2 > Instancias > Connect
# Verás el comando SSH con el usuario correcto


============================================
PASO 2: INSTALAR MYSQL SERVER EN EC2
============================================

# Actualizar paquetes del sistema
sudo apt update && sudo apt upgrade -y

# Instalar MySQL Server
# Debian incluye MySQL Server en los repositorios oficiales
sudo apt install mysql-server -y

# Verificar que MySQL esté corriendo
sudo systemctl status mysql

# Iniciar MySQL si no está corriendo
sudo systemctl start mysql

# Habilitar MySQL para que inicie automáticamente
sudo systemctl enable mysql


============================================
PASO 3: CONFIGURAR MYSQL
============================================

# Ejecutar script de seguridad de MySQL
sudo mysql_secure_installation

Responder las preguntas:
- VALIDATE PASSWORD COMPONENT: No (o Yes si quieres contraseñas fuertes)
- New password: tu_password_mysql (la que pondrás en app.py)
- Re-enter new password: tu_password_mysql
- Remove anonymous users: Yes
- Disallow root login remotely: Yes
- Remove test database: Yes
- Reload privilege tables: Yes

# Acceder a MySQL como root
sudo mysql

# Dentro de MySQL, crear usuario y dar permisos
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'tu_password_mysql';
FLUSH PRIVILEGES;
EXIT;


============================================
PASO 4: CREAR BASE DE DATOS Y TABLA
============================================

# Acceder a MySQL con tu contraseña
mysql -u root -p
# Ingresar: tu_password_mysql

# Dentro de MySQL, crear la base de datos
CREATE DATABASE hackaton;
USE hackaton;

# Crear la tabla equipos
CREATE TABLE equipos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    codigo VARCHAR(50) NOT NULL,
    tipo VARCHAR(50) NOT NULL,
    marcas VARCHAR(50) NOT NULL,
    modelo VARCHAR(100) NOT NULL,
    so VARCHAR(50) NOT NULL,
    almacenamiento INT NOT NULL,
    ram INT NOT NULL,
    estado VARCHAR(50) NOT NULL,
    mantenimiento DATE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

# Verificar que la tabla se creó
SHOW TABLES;
DESCRIBE equipos;
EXIT;

# ALTERNATIVA: Usar el archivo database.sql incluido
mysql -u root -p < database.sql

============================================
PASO 10: CONFIGURAR GUNICORN COMO SERVICIO
============================================

# Crear archivo de servicio systemd
sudo nano /etc/systemd/system/flask-app.service

# Pegar el siguiente contenido (AJUSTAR según tu usuario):

# ==== SI TU USUARIO ES 'admin': ====
[Unit]
Description=Flask Application con Gunicorn
After=network.target

[Service]
User=admin
Group=www-data
WorkingDirectory=/home/admin/ht252S2_wp_AnaFelix
Environment="PATH=/home/admin/ht252S2_wp_AnaFelix/venv/bin"
ExecStart=/home/admin/ht252S2_wp_AnaFelix/venv/bin/gunicorn --workers 3 --bind 0.0.0.0:5000 app:app

[Install]
WantedBy=multi-user.target


# ==== SI TU USUARIO ES 'debian': ====
[Unit]
Description=Flask Application con Gunicorn
After=network.target

[Service]
User=debian
Group=www-data
WorkingDirectory=/home/debian/ht252S2_wp_AnaFelix
Environment="PATH=/home/debian/ht252S2_wp_AnaFelix/venv/bin"
ExecStart=/home/debian/ht252S2_wp_AnaFelix/venv/bin/gunicorn --workers 3 --bind 0.0.0.0:5000 app:app

[Install]
WantedBy=multi-user.target


# Guardar con Ctrl+O, Enter, Ctrl+X

# Recargar systemd
sudo systemctl daemon-reload

# Iniciar el servicio
sudo systemctl start flask-app

# Habilitar inicio automático
sudo systemctl enable flask-app

# Verificar estado
sudo systemctl status flask-app


============================================
PASO 11: CONFIGURAR FIREWALL
============================================

# En Debian, ufw puede no estar instalado por defecto
# Verificar si está instalado:
which ufw

# Si no está instalado:
sudo apt install ufw -y

# Configurar firewall
sudo ufw allow 5000/tcp
sudo ufw allow ssh
sudo ufw --force enable

# Verificar reglas
sudo ufw status


============================================
PASO 12: VERIFICAR EN AWS SECURITY GROUP
============================================

En AWS Console:
1. Ir a EC2 > Instances > Tu Instancia
2. Security > Security Groups
3. Edit inbound rules
4. Agregar regla:
   - Type: Custom TCP
   - Port Range: 5000
   - Source: 0.0.0.0/0 (o tu IP específica)
5. Save rules

============================================
TROUBLESHOOTING
============================================

ERROR: No se puede conectar a MySQL
SOLUCIÓN: 
- Verificar que MySQL esté corriendo: sudo systemctl status mysql
- Verificar contraseña en app.py
- Verificar que la base de datos existe: mysql -u root -p -e "SHOW DATABASES;"
- En Debian, verificar logs: sudo tail -f /var/log/mysql/error.log

ERROR: ModuleNotFoundError: No module named 'MySQLdb'
SOLUCIÓN:
- source venv/bin/activate
- pip install mysqlclient
- Si falla, instalar dependencias: sudo apt install python3-dev default-libmysqlclient-dev

ERROR: 502 Bad Gateway
SOLUCIÓN:
- Verificar que gunicorn esté corriendo: sudo systemctl status flask-app
- Ver logs: sudo journalctl -u flask-app -f
- Verificar que el puerto 5000 esté disponible: sudo netstat -tulpn | grep 5000

ERROR: La aplicación no carga
SOLUCIÓN:
- Verificar Security Group en AWS (puerto 5000 abierto)
- Verificar firewall: sudo ufw status
- Probar localmente: curl http://localhost:5000

ERROR: Permission denied (publickey)
SOLUCIÓN:
- Verificar que estás usando el usuario correcto (admin o debian)
- Verificar permisos de la clave: chmod 400 tu-clave.pem
- Verificar que la clave sea la correcta en AWS Console

ERROR: www-data group does not exist
SOLUCIÓN:
- Crear el grupo: sudo groupadd www-data
- O cambiar a otro grupo existente: groups (para ver grupos disponibles)

============================================
DIFERENCIAS CLAVE DEBIAN VS UBUNTU
============================================

1. USUARIO POR DEFECTO:
   Ubuntu: ubuntu
   Debian: admin o debian

2. FIREWALL:
   Ubuntu: ufw incluido por defecto
   Debian: necesita instalación manual

3. VERSIONES DE PAQUETES:
   Ubuntu: Versiones más recientes
   Debian: Versiones más estables (a veces antiguas)

4. ACTUALIZACIONES:
   Ubuntu: Actualizaciones más frecuentes
   Debian: Ciclo de lanzamiento más largo

5. REPOSITORIOS:
   Ambos usan apt, pero Debian puede tener menos paquetes third-party

============================================
NOTAS IMPORTANTES
============================================

1. SEGURIDAD:
   - Cambiar 'tu_password_mysql' por una contraseña fuerte
   - No compartir las credenciales de MySQL
   - Considerar usar certificado SSL/TLS para producción
   - Mantener el sistema actualizado: sudo apt update && sudo apt upgrade

2. PRODUCCIÓN:
   - Configurar Nginx como reverse proxy
   - Configurar SSL con Let's Encrypt
   - Implementar sistema de logs
   - Configurar backups automáticos de MySQL
   - Configurar monitoreo (Prometheus, Grafana, etc.)

3. MANTENIMIENTO:
   - Actualizar paquetes regularmente: sudo apt update && sudo apt upgrade
   - Monitorear espacio en disco: df -h
   - Monitorear memoria: free -h
   - Revisar logs periódicamente: sudo journalctl -xe
   - Limpiar paquetes antiguos: sudo apt autoremove

4. BASE DE DATOS:
   - La base de datos está en la misma instancia (localhost)
   - Los datos se almacenan en /var/lib/mysql/
   - Hacer backups regularmente
   - Monitorear tamaño de tablas: 
     mysql -u root -p -e "SELECT table_schema, SUM(data_length + index_length) / 1024 / 1024 AS 'Size (MB)' FROM information_schema.tables GROUP BY table_schema;"

5. RENDIMIENTO:
   - Ajustar número de workers de Gunicorn según CPU: (2 * CPU_cores) + 1
   - Monitorear uso de recursos: htop (instalarlo con: sudo apt install htop)
   - Configurar swap si es necesario
