INBOUND SECURITY GROUP RULES:

Regla 1 - SSH (Acceso remoto):
┌──────────────┬──────────┬───────────┬──────────────┐
│ Type         │ Protocol │ Port Range│ Source type  │
├──────────────┼──────────┼───────────┼──────────────┤

PASO 11: CREAR IP ELÁSTICA
---------------------------

EXPLICACIÓN:
La IP pública asignada automáticamente cambia si reinicias la instancia.
Una IP Elástica es permanente y no cambia.

1. En EC2 Dashboard, panel izquierdo: Network & Security > Elastic IPs

2. Click "Allocate Elastic IP address"

3. Configurar:
   Network Border Group:
   ┌─────────────────────────────────┐
   │ us-east-1 (o tu región)         │
   └─────────────────────────────────┘

   Public IPv4 address pool:
   ○ Amazon's pool of IPv4 addresses ✓

4. Tags (opcional):
   Key: Name, Value: hackaton-eip

5. Click "Allocate"

6. Ver mensaje de éxito:
   ✅ Successfully allocated Elastic IP address
   
   New address: 98.87.67.95 (ejemplo)

⚠️ IMPORTANTE: 
- IP Elástica es GRATIS si está asociada a instancia en ejecución
- Cobra $0.005/hora (~$3.60/mes) si está SIN USAR
- SIEMPRE asociarla a una instancia o liberarla


PASO 12: ASOCIAR IP ELÁSTICA A INSTANCIA
-----------------------------------------

1. Seleccionar la IP Elástica recién creada (98.87.67.95)

2. Actions > Associate Elastic IP address

3. Configurar:
   Resource type:
   ○ Instance ✓
   ○ Network interface

   Instance:
   ┌─────────────────────────────────┐
   │ i-xxx hackaton-flask-app        │
   └─────────────────────────────────┘

   Private IP address:
   ┌─────────────────────────────────┐
   │ 172.31.x.x (se llena automático)│
   └─────────────────────────────────┘

   ☑ Allow this Elastic IP address to be reassociated

4. Click "Associate"

5. Ver mensaje de éxito:
   ✅ Successfully associated Elastic IP address

6. Volver a EC2 > Instances

7. Verificar que "Public IPv4 address" ahora es: 98.87.67.95

GUARDAR ESTA IP:
┌─────────────────────────────────┐
│ IP Elástica: 98.87.67.95        │
└─────────────────────────────────┘

Esta es tu IP PERMANENTE para acceder a la aplicación.

PASO 14: CONECTAR VÍA SSH
--------------------------

Desde PowerShell:

```powershell
ssh -i "C:\Users\anacr\Downloads\ani.pem" ubuntu@98.87.67.95
```

EXPLICACIÓN:
- ssh: Comando para conexión segura
- -i: Especifica archivo de clave privada
- ubuntu: Usuario por defecto en Ubuntu AMI
- 98.87.67.95: Tu IP Elástica

Primera vez que te conectas:

Verás mensaje:
```
The authenticity of host '98.87.67.95 (98.87.67.95)' can't be established.
ECDSA key fingerprint is SHA256:abc123...
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Escribir: yes

Ver mensaje de bienvenida:
```
Welcome to Ubuntu 22.04.3 LTS (GNU/Linux 6.2.0-1009-aws x86_64)

 * Documentation:  https://help.ubuntu.com
 * Management:     https://landscape.canonical.com
 * Support:        https://ubuntu.com/advantage

ubuntu@ip-172-31-x-x:~$
```

✅ ¡Conectado exitosamente!


SOLUCIÓN DE PROBLEMAS DE CONEXIÓN:

ERROR: "Permission denied (publickey)"
SOLUCIÓN:
- Verificar que usas usuario "ubuntu" (no "root" o "admin")
- Verificar ruta correcta del archivo .pem
- Verificar que descargaste la clave correcta

ERROR: "Connection timed out"
SOLUCIÓN:
- Verificar Security Group permite puerto 22 desde tu IP
- Verificar que usas la IP Elástica correcta
- Verificar que la instancia está en estado "Running"

ERROR: "Host key verification failed"
SOLUCIÓN:
- Eliminar entrada antigua: ssh-keygen -R 98.87.67.95
- Intentar conectar nuevamente

PASO 36: CREAR ARCHIVO DE SERVICIO SYSTEMD
-------------------------------------------

```bash
# Crear archivo de servicio
sudo nano /etc/systemd/system/flask-app.service
```

Copiar el siguiente contenido:

```ini
[Unit]
Description=Flask Application con Gunicorn conectado a AWS RDS
After=network.target

[Service]
User=ubuntu
Group=www-data
WorkingDirectory=/home/ubuntu/ht252S2_wp_AnaFelix
Environment="PATH=/home/ubuntu/ht252S2_wp_AnaFelix/venv/bin"
ExecStart=/home/ubuntu/ht252S2_wp_AnaFelix/venv/bin/gunicorn --workers 3 --bind 0.0.0.0:5000 app:app

[Install]
WantedBy=multi-user.target
```

EXPLICACIÓN LÍNEA POR LÍNEA:

**[Unit]**
- Description: Descripción del servicio
- After=network.target: Iniciar después de que la red esté disponible

**[Service]**
- User=ubuntu: Ejecutar como usuario ubuntu
- Group=www-data: Grupo www-data (estándar para servicios web)
- WorkingDirectory: Directorio del proyecto
- Environment="PATH=...": Usar Python del entorno virtual
- ExecStart: Comando para iniciar Gunicorn
  * --workers 3: 3 procesos worker (fórmula: (2 x CPU) + 1)
  * --bind 0.0.0.0:5000: Escuchar en todas las interfaces, puerto 5000
  * app:app: módulo:variable de Flask

**[Install]**
- WantedBy=multi-user.target: Iniciar en modo multi-usuario

Guardar archivo:
- Ctrl + O (Write Out)
- Enter
- Ctrl + X (Exit)

PASO 46: OPTIMIZAR GUNICORN
----------------------------

**Aumentar Workers:**

Fórmula: (2 x CPU cores) + 1

Para t2.micro (1 CPU):
```
--workers 3
```

Para t3.medium (2 CPU):
```
--workers 5
```

Editar servicio:
```bash
sudo nano /etc/systemd/system/flask-app.service

# Cambiar línea ExecStart
ExecStart=/home/ubuntu/ht252S2_wp_AnaFelix/venv/bin/gunicorn --workers 5 --bind 0.0.0.0:5000 app:app

sudo systemctl daemon-reload
sudo systemctl restart flask-app
```

**Agregar Timeout:**
```bash
ExecStart=.../gunicorn --workers 3 --bind 0.0.0.0:5000 --timeout 60 app:app
```

**Usar Threads:**
```bash
ExecStart=.../gunicorn --workers 3 --threads 2 --bind 0.0.0.0:5000 app:app
```


PASO 47: CONFIGURAR NGINX COMO REVERSE PROXY (OPCIONAL)
--------------------------------------------------------

VENTAJAS:
- Mejor manejo de archivos estáticos
- Soporte SSL/TLS
- Compresión gzip
- Caché de respuestas

```bash
# Instalar Nginx
sudo apt install -y nginx

# Crear configuración
sudo nano /etc/nginx/sites-available/flask-app
```

Contenido:
```nginx
server {
    listen 80;
    server_name 98.87.67.95;

    # Logs
    access_log /var/log/nginx/flask-app-access.log;
    error_log /var/log/nginx/flask-app-error.log;

    # Archivos estáticos
    location /static {
        alias /home/ubuntu/ht252S2_wp_AnaFelix/static;
    }

    # Proxy a Gunicorn
    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Activar configuración:
```bash
sudo ln -s /etc/nginx/sites-available/flask-app /etc/nginx/sites-enabled/
sudo rm /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl restart nginx
```

Cambiar Gunicorn a localhost:
```bash
sudo nano /etc/systemd/system/flask-app.service

# Cambiar --bind 0.0.0.0:5000 a --bind 127.0.0.1:5000
ExecStart=.../gunicorn --workers 3 --bind 127.0.0.1:5000 app:app

sudo systemctl restart flask-app
```
