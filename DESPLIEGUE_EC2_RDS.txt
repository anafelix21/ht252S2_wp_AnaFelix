PARTE 1: CREAR Y CONFIGURAR AWS RDS (BASE DE DATOS)
============================================

PASO 1: CREAR INSTANCIA RDS MYSQL
------------------------------------

1. Ir a AWS Console > RDS > Databases
2. Click en "Create database"
3. Configurar los siguientes parámetros:

   MÉTODO DE CREACIÓN:
   - Choose a database creation method: Standard create

   OPCIONES DEL MOTOR:
   - Engine type: MySQL
   - Engine Version: MySQL 8.0.x (última versión disponible)

   PLANTILLAS:
   - Templates: Free tier (para desarrollo/prueba)
     * O "Production" si es para producción real

   CONFIGURACIÓN:
   - DB instance identifier: hackaton-mysql-db
   - Master username: admin
   - Master password: TuPasswordSeguro123!
   - Confirm password: TuPasswordSeguro123!

   CONFIGURACIÓN DE INSTANCIA:
   - DB instance class: 
     * Free tier: db.t3.micro (1 vCPU, 1 GB RAM)
     * Production: db.t3.small o superior
   
   ALMACENAMIENTO:
   - Storage type: General Purpose SSD (gp3)
   - Allocated storage: 20 GB (mínimo para free tier)
   - Enable storage autoscaling: ✓ (opcional)
   - Maximum storage threshold: 100 GB

   CONECTIVIDAD:
   - Compute resource: Don't connect to an EC2 compute resource
   - Virtual private cloud (VPC): Default VPC
   - Public access: Yes (para desarrollo)
     * En producción usar "No" y conectar vía VPC peering
   - VPC security group: Create new
   - New VPC security group name: rds-hackaton-sg

   AUTENTICACIÓN DE BASE DE DATOS:
   - Database authentication: Password authentication

   CONFIGURACIÓN ADICIONAL:
   - Initial database name: hackaton
   - Backup retention period: 7 days
   - Enable encryption: ✓ (recomendado)

4. Click "Create database"
5. Esperar 5-10 minutos hasta que el estado sea "Available"


PASO 2: CONFIGURAR SECURITY GROUP DE RDS
-----------------------------------------

1. Ir a RDS > Databases > hackaton-mysql-db
2. En la sección "Connectivity & security", copiar el "Endpoint"
   Ejemplo: hackaton-mysql-db.c9akciq32.us-east-1.rds.amazonaws.com

3. Click en el Security Group (rds-hackaton-sg)
4. Click en "Edit inbound rules"
5. Configurar regla para MySQL:

   REGLA DE ENTRADA:
   - Type: MYSQL/Aurora
   - Protocol: TCP
   - Port Range: 3306
   - Source: Custom
     * Opción 1 (Desarrollo): 0.0.0.0/0 (cualquier IP)
     * Opción 2 (Producción): Security Group de EC2
     * Opción 3 (Seguro): Tu IP específica
   - Description: MySQL access from EC2

6. Click "Save rules"

PARTE 4: SEGURIDAD Y MEJORES PRÁCTICAS
============================================

CONFIGURACIÓN DE SEGURIDAD PARA RDS
------------------------------------

1. RESTRINGIR ACCESO A RDS:
   - En producción, cambiar Security Group de RDS
   - Source: Solo el Security Group de EC2
   - NO usar 0.0.0.0/0 en producción

2. USAR SECRETS MANAGER:
   - Almacenar credenciales de RDS en AWS Secrets Manager
   - Modificar app.py para leer credenciales desde Secrets Manager
   
   Ejemplo básico:
   ```python
   import boto3
   import json
   
   def get_secret():
       secret_name = "rds-hackaton-credentials"
       region_name = "us-east-1"
       
       session = boto3.session.Session()
       client = session.client(service_name='secretsmanager', region_name=region_name)
       
       get_secret_value_response = client.get_secret_value(SecretId=secret_name)
       secret = json.loads(get_secret_value_response['SecretString'])
       return secret
   
   secret = get_secret()
   app.config['MYSQL_HOST'] = secret['host']
   app.config['MYSQL_USER'] = secret['username']
   app.config['MYSQL_PASSWORD'] = secret['password']
   ```

3. HABILITAR SSL/TLS:
   - Descargar certificado RDS desde AWS
   - Configurar conexión SSL en app.py

4. BACKUPS AUTOMÁTICOS:
   - Verificar que están habilitados (ya configurado en PASO 1)
   - Retention period: 7 días mínimo
   - Snapshot automático diario

5. MONITORING:
   - Habilitar Enhanced Monitoring en RDS
   - Configurar CloudWatch Alarms para:
     * CPU utilization > 80%
     * Free storage < 2 GB
     * Database connections > 100


CONFIGURACIÓN DE SEGURIDAD PARA EC2
------------------------------------

1. ACTUALIZAR SISTEMA REGULARMENTE:
   sudo apt update && sudo apt upgrade -y

2. CONFIGURAR SSL/TLS CON NGINX (OPCIONAL):
   - Instalar Nginx como reverse proxy
   - Obtener certificado SSL con Let's Encrypt
   - Configurar HTTPS

3. LIMITAR ACCESO SSH:
   - Cambiar Security Group SSH Source a "My IP"
   - Considerar usar AWS Systems Manager Session Manager

4. CONFIGURAR IAM ROLES:
   - Crear IAM Role para EC2
   - Asignar permisos mínimos necesarios
   - NO usar credenciales hardcoded

SOLUCIÓN:
- source venv/bin/activate
- pip install mysqlclient
- Si falla: sudo apt install python3-dev default-libmysqlclient-dev

ERROR: OperationalError: (2003, "Can't connect to MySQL server")
SOLUCIÓN:

- Verificar endpoint y puerto (3306)
- Verificar Security Groups
- Verificar que Public accessibility está en "Yes"

ERROR: 502 Bad Gateway

ERROR: Access denied for user 'admin'@'X.X.X.X'
SOLUCIÓN:
- Verificar contraseña correcta

- Verificar servicio: sudo systemctl status flask-app

OPTIMIZAR RENDIMIENTO DE RDS
-----------------------------

1. AJUSTAR PARÁMETROS DE RDS:
   - RDS > Parameter groups > Create parameter group
   - Ajustar:
     * max_connections (default: 151, aumentar si necesario)
     * innodb_buffer_pool_size (70-80% de RAM disponible)
     * query_cache_size (para consultas repetidas)

2. ÍNDICES EN BASE DE DATOS:
   CREATE INDEX idx_codigo ON equipos(codigo);
   CREATE INDEX idx_tipo ON equipos(tipo);
   CREATE INDEX idx_estado ON equipos(estado);

3. USAR READ REPLICAS:
   - Para aplicaciones con muchas lecturas
   - Crear Read Replica desde AWS Console
   - Configurar app.py para leer desde replica

4. HABILITAR MULTI-AZ:
   - Para alta disponibilidad en producción
   - RDS > Modify > Multi-AZ deployment: Yes


OPTIMIZAR RENDIMIENTO DE EC2
-----------------------------

1. AUMENTAR WORKERS DE GUNICORN:
   # En flask-app.service, cambiar:
   ExecStart=.../gunicorn --workers 5 --bind 0.0.0.0:5000 app:app
   # Fórmula: workers = (2 x CPU_cores) + 1

2. USAR NGINX COMO REVERSE PROXY:
   sudo apt install nginx -y
   
   # Configurar /etc/nginx/sites-available/flask-app:
   server {
       listen 80;
       server_name 98.87.67.95;
       
       location / {
           proxy_pass http://127.0.0.1:5000;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
       }
   }
   
   sudo ln -s /etc/nginx/sites-available/flask-app /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl restart nginx

3. CONFIGURAR CACHE:
   - Redis para sesiones
   - Memcached para queries
   - CloudFront CDN para assets estáticos

4. AUTO SCALING:
   - Crear AMI de tu EC2 configurada
   - Crear Launch Template
   - Configurar Auto Scaling Group
   - Configurar Load Balancer
